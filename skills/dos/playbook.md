# 拒绝服务（DoS）

> 视角：黑盒，用最小流量证明「继续打目标就死」，绝不真打死。判断流程优先，payload 靠现场构造不背。

## 排他声明（触发即停的一级声明）
仅当目标是「证明放大导致不可用」。
- 单次请求目的是读数据（actuator/env 读配置）→ info-disclosure，别按 DoS 报
- rate limit 不够但不能放大 → SRC 通常不收，直接放弃
- 缓存投毒能控制响应内容 → 先按 Web cache poisoning
- **无授权不做生产负载 / 不做 sustained / 不做并发 / 缓存投毒必带 cachebuster**

## 一句话说清
DoS = 让服务资源消耗远超正常请求所需。放大比 = 攻击成本 / 目标资源消耗，≥ 1:1000 → P3，≥ 1:100000 或单包打死 → P2/P1。

## 判断流程（★ 核心）

### Step 1 — 基线（1 次请求）
正常请求记 time_total + http_code。

### Step 2 — 二倍递增（n=10→50，每个 n 只发 1 包）
对候选字段发递增长度 payload（如 `'a'*n + '!'`），记录每个 n 的响应时间。

### Step 3 — 判据（时间曲线）
- n 每 +10 时间 ≥ 4×（接近 2^k 指数）→ ReDoS 确认，**立即停，不再加大 n**
- 时间线性增长 → 转「资源不限速」路径（无算法放大，只能证明缺 quota/cap，SRC 通常不收）
- 3 个候选端点都无放大 → 判定无应用层 DoS，停止，不再换 payload fuzz

### Step 4 — 复现（确认后）
不再加大 payload，按模板写 5 次串行复现（每次 ≤60s，不并发），附放大比公式 + 时间曲线。

## 真实 CVE 案例（精简，嵌在类型里的保留）
- CVE-2023-28756 Ruby Time.rfc2822 ReDoS（Rack 自动调用，HTTP 请求即触发）
- CVE-2024-27983 Node.js HTTP/2、CVE-2024-34750 Tomcat HTTP/2 DoS
- GitLab #1543718：preview_markdown 1MB 嵌套图片 CPU 60s/请求
- Exodus #1173153 / GitLab #1160407：缓存投毒 DoS

## 响应特征 → 结论映射（保留）
| 现象 | 结论 |
|---|---|
| 200 但响应 >30s | 算法漏洞/慢查询 |
| 502/504 | 上游已打死或 timeout |
| 503 + Retry-After | 限速生效（保护到位） |
| Cache-Status/X-Cache HIT 错误页 | 缓存投毒成功 |
| 无 429 + 同接口高频成功 | 限速缺失 |

## scope 接不接清单（保留）
- 不收：网络层洪水（SYN/UDP/反射）、rate limit 不够但不能放大、仅本地 PoC fork bomb
- 收：单/少量请求耗尽全局资源、缓存投毒、算法复杂度（ReDoS/哈希碰撞/O(n²)）、绕过 rate limit 后轰炸、解释器 segfault

## 合规铁则（保留，最敏感）
- 无授权不做生产负载测试；PoC 单次 ≤60s，不并发，全串行
- sustained DoS / 真实 DDoS / 反射放大 → 违法 + 违 ToS，永不真打
- 缓存投毒必带 `?cachebuster=$(uuidgen)` 或自定义 path，防污染共享缓存
- 短信/邮件轰炸证明「不限速」5–10 次即止，不发 1000 条
- 只打自己的测试账号

## 证据 / 不要做的事（精简）
- 报告明示三件事：小流量证明放大 + 立即停止 + 未影响他人
- 放大比公式 + 5 次串行复现 timing + 时间曲线
- 一句话给运营：DoS ≠ 服务慢，是「单位资源消耗 × 业务影响」超设计假设；修复三选一：限大小、限时间、限频率
- CVSS 4.0 典型：未授权应用层 DoS 8.7 High / 限速绕过（无放大）6.9 Medium
